Whole phase in one paragraph

Phase 4 had one goal: one reproducible, fair row against fx. We worked in measurement mode and added no features. We ran 8 live sets on one task family (T1). Most sets are weak. The first fixture (T1 v1) had fix hints in the source. Some sets failed because one agent could not start on a provider. Free-tier quota stopped other sets. The one fair row is T1 v2 on gemini-3.5-flash-lite, through our bench proxy, with 5 s pacing for both agents. In that row both agents solved the task 3 of 3 times. Harness used fewer input tokens on this one task. We also found and fixed two real key-leak bugs. The data does not yet name a Harness weakness to fix. T7 and T9 runs are in progress.

1. Executive summary

  • One fair row. T1 v2, Flash-Lite, proxy, 5 s pacing. Harness 3/3. fx 3/3. This is a tie on success.
  • Input tokens on that row: Harness median 28,833. fx median 75,499. This is one task, one weak model, n = 3. We do not know why the gap exists.
  • Turns: Harness 14 model turns, fx 10 steps. These units are different. On one shared unit (model requests counted at the proxy), Harness 14 and fx 15. The gap almost closes.
  • Wall time minus pacing: Harness 11.0 s, fx 12.8 s (medians). This is close. We make no speed claim.
  • Under quota pressure, Harness stopped on a 429 in 1 of 3 unpaced runs. fx finished 3 of 3. A rate limit was in play, so this is a "watch" item, not a "fix" item.
  • Security: we found and fixed two key-leak bugs in the scrub code. No key appeared in any run folder, doc or commit.
  • What to build next: nothing yet. Add tasks. T7 and T9 must answer first.
